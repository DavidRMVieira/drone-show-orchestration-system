# General Glossary

**TEA -> Terms, Expressions, and Acronyms**

| **_TEA_ (EN)**                        | **_Description_ (EN)**                                                                                                                                                                                                                                                                                 |
|:--------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **AC**                                | Acronym for "Acceptance Criteria".                                                                                                                                                                                                                                                                     |
| **Acceptance Criteria**               | Specific criteria that a solution must fulfill to be approved.                                                                                                                                                                                                                                         |
| **Administrator**                     | User with permissions to manage users and system configurations.                                                                                                                                                                                                                                       | 
| **Agile**                             | A methodology for iterative and incremental development.                                                                                                                                                                                                                                               | 
| **ANTLR**                             | Tool used to generate syntax analyzers and validate the DSL language.                                                                                                                                                                                                                                  | 
| **API**                               | Acronym for "Application Programming Interface".                                                                                                                                                                                                                                                       |
| **Application Programming Interface** | Set of definitions and protocols for system integration.                                                                                                                                                                                                                                               |
| **Applications Engineering**          | A course focused on the development of applications and software systems, emphasizing techniques, tools, and methodologies to ensure the final product meets requirements and is efficient and scalable.                                                                                               |
| **Authentication**                    | Process of verifying a user’s identity before granting access to the system.                                                                                                                                                                                                                           |
| **Authorization**                     | Process that determines the access rights of an authenticated user.                                                                                                                                                                                                                                    |
| **Backlog**                           | A list of tasks or orders that are still pending.                                                                                                                                                                                                                                                      |
| **Backoffice**                        | Administrative interface used by internal users of Shodrone.                                                                                                                                                                                                                                           |
| **Bootstrap Process**                 | Initial procedure for configuring users, clients, and drones in the system.                                                                                                                                                                                                                            |
| **Client**                            | Company or entity that contracts Shodrone's services for drone shows.                                                                                                                                                                                                                                  |
| **Client Representative**             | Person who interacts with Shodrone on behalf of the client company.                                                                                                                                                                                                                                    |
| **Concurrency**                       | Refers to the ability of a system to handle multiple tasks or processes at the same time.                                                                                                                                                                                                              |
| **Collision**                         | Event where two drones occupy the same space at the same time in the simulation.                                                                                                                                                                                                                       |
| **Commit**                            | Submission of code and documents to the project repository.                                                                                                                                                                                                                                            |
| **Computer Networks**                 | A course that deals with the principles, protocols, and technologies behind computer networks. It covers everything from basic data communication to the more complex infrastructures that form the internet and other networks.                                                                       |
| **Computer Systems**                  | The study of computer system architectures, focusing on the functioning of hardware, operating systems, and interactions between system components. This course is essential for understanding the underlying infrastructure of software.                                                              |
| **Continuous Integration**            | Automation process for continuous integration and validation of code.                                                                                                                                                                                                                                  |
| **CI**                                | Acronym for "Continuous Integration".                                                                                                                                                                                                                                                                  |
| **Customer Relationship Management**  | System for managing customer relationships.                                                                                                                                                                                                                                                            |
| **CRM**                               | Acronym for "Customer Relationship Management".                                                                                                                                                                                                                                                        |
| **CRM Collaborator**                  | User who assists in managing customer relationships by handling client interactions, maintaining records, and supporting CRM operations.                                                                                                                                                               |
| **CRM Manager**                       | User responsible for overseeing customer relationships, managing client accounts, and ensuring smooth communication between the company and clients.                                                                                                                                                   |
| **Deployment**                        | The process of releasing and setting up a software system in a production environment.                                                                                                                                                                                                                 |
| **Debugging**                         | The process of identifying and fixing issues in the code.                                                                                                                                                                                                                                              |
| **Drone**                             | Unmanned aerial vehicle used to create figures and sequences in the shows.                                                                                                                                                                                                                             |
| **Drone Inventory**                   | Record of drone models and their characteristics in the system.                                                                                                                                                                                                                                        |
| **Drone Tech**                        | Role responsible for managing the technical aspects of drones, including inventory and testing.                                                                                                                                                                                                        |
| **Domain Model**                      | Structure that represents the system's elements and their relationships.                                                                                                                                                                                                                               |
| **DDD**                               | Acronym for "Domain-Driven Design".                                                                                                                                                                                                                                                                    |
| **Domain Specific Language**          | High-level language used to describe figures and sequences in drone shows.                                                                                                                                                                                                                             |
| **DSL**                               | Acronym for "Domain Specific Language".                                                                                                                                                                                                                                                                |
| **EAPLI**                             | Acronym for "Applications Engineering".                                                                                                                                                                                                                                                                |
| **Edge Computing**                    | Distributed computing model that processes data at the network's edge, reducing latency.                                                                                                                                                                                                               |
| **Error Handling**                    | Mechanisms for managing runtime errors or unexpected conditions in a system.                                                                                                                                                                                                                           |
| **Figure**                            | Shape or pattern created by drones during a show.                                                                                                                                                                                                                                                      |
| **Framework**                         | Set of libraries and tools used for software development.                                                                                                                                                                                                                                              |
| **GitHub**                            | Platform for managing code repositories used in the project.                                                                                                                                                                                                                                           |
| **Iteration**                         | Each development cycle in the project, corresponding to a sprint.                                                                                                                                                                                                                                      |
| **Java**                              | A high-level programming language used to create applications.                                                                                                                                                                                                                                         |
| **Javadoc**                           | A tool that generates API documentation in HTML format from Java source code.                                                                                                                                                                                                                          |
| **Laboratory and Project IV**         | A practical course that allows students to develop integration projects, applying knowledge from previous subjects. The goal is to develop problem-solving skills and teamwork.                                                                                                                        |
| **Languages and Programming**         | The study of programming languages and their applications in software development. The course covers basic and advanced programming concepts, algorithms, data structures, and programming paradigms.                                                                                                  |
| **LAPR4**                             | Acronym for "Laboratory and Project IV".                                                                                                                                                                                                                                                               |
| **LPROG**                             | Acronym for "Languages and Programming".                                                                                                                                                                                                                                                               |
| **Laboratory Practices**              | Classes dedicated to the practical development of the project.                                                                                                                                                                                                                                         |
| **Mutex**                             | Synchronization mechanism to prevent concurrent access to shared resources.                                                                                                                                                                                                                            |
| **Non-Functional Requirements**       | Non-functional requirements that define quality and performance standards.                                                                                                                                                                                                                             |
| **NFR**                               | Acronym for "Non-Functional Requirements".                                                                                                                                                                                                                                                             |
| **Pipes**                             | Communication channels used to transmit data between processes in a concurrent system.                                                                                                                                                                                                                 |
| **PL**                                | Acronym for "Laboratory Practices".                                                                                                                                                                                                                                                                    |
| **Plugin**                            | Additional module used to analyze and validate DSL code and drone programming language.                                                                                                                                                                                                                |
| **Processes**                         | Mechanisms used to implement the concurrent execution of drones, often represented as a program running with its own resources.                                                                                                                                                                        |
| **Product Owner**                     | Responsible for defining project priorities and requirements.                                                                                                                                                                                                                                          |
| **PO**                                | Acronym for "Product Owner".                                                                                                                                                                                                                                                                           |
| **Repository**                        | Location in GitHub where the project’s code is stored and managed.                                                                                                                                                                                                                                     |
| **RCOMP**                             | Acronym for "Computer Networks".                                                                                                                                                                                                                                                                       |
| **SCOMP**                             | Acronym for "Computer Systems".                                                                                                                                                                                                                                                                        |
| **Scrum**                             | Agile methodology used for project management.                                                                                                                                                                                                                                                         |
| **Scrum Master**                      | Role responsible for facilitating Scrum ceremonies, ensuring the team follows Scrum practices, and removing impediments to the team’s progress.                                                                                                                                                        |
| **Semaphore**                         | Control structure used to manage process synchronization.                                                                                                                                                                                                                                              |
| **Shodrone**                          | An autonomous delivery system based on drones, designed to optimize the distribution of packages in urban and industrial environments. Shodrone integrates autonomous navigation technology, obstacle detection sensors, and a real-time communication system to ensure safe and efficient deliveries. |
| **Show Designer**                     | Responsible for creating figures and sequences.                                                                                                                                                                                                                                                        |
| **Show Proposal**                     | Show proposal sent to the client.                                                                                                                                                                                                                                                                      |
| **Signals**                           | Notifications sent to processes to indicate events or request actions, commonly used for inter-process communication.                                                                                                                                                                                  |
| **Simulation**                        | Process that checks for collisions and validates figures and shows before the actual execution.                                                                                                                                                                                                        |
| **Simulation Model**                  | A representation of the system used for testing and validating various scenarios in a controlled environment.                                                                                                                                                                                          |
| **Sprint**                            | Development period with defined goals.                                                                                                                                                                                                                                                                 |
| **Step-by-Step Simulation**           | Mechanism that synchronizes drone execution in controlled time steps.                                                                                                                                                                                                                                  |
| **Structured Query Language**         | Language used for interaction with relational databases.                                                                                                                                                                                                                                               |
| **SQL**                               | Acronym for "Structured Query Language".                                                                                                                                                                                                                                                               |
| **Test-Driven Development**           | Development approach where tests are written before functional code.                                                                                                                                                                                                                                   |
| **TDD**                               | Acronym for "Test-Driven Development".                                                                                                                                                                                                                                                                 |
| **Thread**                            | Execution unit within a process.                                                                                                                                                                                                                                                                       |
| **Use Case**                          | Representation of user interactions with the system.                                                                                                                                                                                                                                                   |
| **User Story**                        | Short description of a required functionality in the system.                                                                                                                                                                                                                                           |
| **US**                                | Acronym for "User Story".                                                                                                                                                                                                                                                                              |
| **Version Control**                   | A system that tracks changes in code over time, allowing for collaboration and historical tracking.                                                                                                                                                                                                    |
